# ADR-0015：不可信内容信任边界与提示词投毒分层防御

**状态：** Accepted
**日期：** 2026-09-12

## 背景

Vera 已把 Provider 输出和工具参数视为不可信输入，并由 Workspace、PolicyEngine、ApprovalGate 和 Runtime 执行确定性校验。工程文件、项目说明、命令输出、会话摘要和模型输出仍可能被拼进同一权限层，使伪装成指令的文本获得用户目标或系统策略的地位。

用户已确认[不可信内容、提示词投毒与内容安全](../specs/2026-09-12-untrusted-content-and-prompt-injection-defense.md)。本决策固化阶段五安全增量必须遵守的信任边界，不把检测器或内容审核当成授权来源。

## 决策

- 采用分层防御：来源与权限分离 → 可选风险检测 → PolicyEngine 确定性动作策略 → 参数绑定审批 → 对抗评测。
- 指令权限从高到低为：内置安全策略 → 用户当前目标与针对具体动作的有效审批 → 用户明确启用的本地配置 → 工程约定（仅建议）→ 工程文件、工具输出、摘要、模型输出和未来外部数据（无指令权限）。
- 使用 UI 无关的 `ContentEnvelope` 记录 `source_kind`、`origin`、`trust_level`、`content_hash`、截断状态和可选 `risk_labels`。来源缺失、未知或解析失败一律视为 `untrusted`。
- 上下文压缩不得把不可信内容提升为 System 或用户指令；摘要继承输入中的最低信任级别。
- 风险检测器只产生 `allow`、`warn`、`quarantine` 或 `block`，且只能保持或收紧 PolicyEngine 决策，不能放宽、不能跳过审批、不能生成权限。
- 检测器超时、崩溃或结果无效时不得扩大权限；只读工作可在确定性边界内继续，写入、命令、恢复和迁移必须失败关闭或要求明确审批。
- `ContentSafetyPolicy` 作为供应商无关接口保留，阶段五不接入外部审核服务，也不默认把用户源码发送给新的第三方。
- 公共 Event 只记录来源、hash、风险类别、决策、原因码和策略版本，不记录被标记原文。
- 合法安全分析、攻击样本和含敏感词的代码不得仅因关键词命中而被拒绝。

## 备选方案

### 关键词过滤作为主机制

实现简单，但易被编码与伪装绕过，也会误拒绝安全研究，因此不采用。

### 单独使用 Guardrail 模型作为授权

覆盖面更好，但分类器可被投毒、误判或不可用，且增加隐私与延迟，因此不能成为授权边界。

### 允许工程说明修改安全边界

不可信仓库可以借 `AGENTS.md` 或 README 扩大本机权限，因此不采用。

## 后果

- CLI、JSON、评测和未来桌面客户端消费同一来源与风险事实，不自行重新分类。
- 检测漏报仍不能绕过 Workspace、PolicyEngine 和 ApprovalGate。
- 公开内容政策、远程审核开关和 MCP/网页出站场景留到后续阶段。

## 验证与重审触发器

- 固定对抗夹具证明未批准写入、危险命令、越界访问和秘密泄漏被阻止。
- 检测器失败和未知来源有稳定失败行为。
- 引入网络工具、MCP、远程审核或公开内容政策时必须重审本决策。
