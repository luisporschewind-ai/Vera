# ADR-0005：确定性 Run 恢复边界

**状态：** Accepted
**日期：** 2026-09-11

## 背景

阶段一只在进程内保存 `RunContext`。Event Journal 和 Checkpoint 可以证明部分历史事实，但不足以从任意中断点还原模型消息、Change Set 私有内容、待审批对象和验证进度。直接把所有未结束 run 描述为“可续跑”会重复执行副作用或覆盖用户修改。

## 决策

- 只在完整、可重新校验的稳定边界保存版本化 `RecoverySnapshot`。
- 重启后由 UI 无关的 `RecoveryCoordinator` 联合检查 Snapshot、Journal、Checkpoint 和当前文件哈希。
- 启动扫描只读，不自动执行恢复、文件写入、验证命令或模型请求。
- 恢复分类固定为 `resumable_approval`、`resumable_verification`、`safe_to_abandon`、`recoverable_partial_apply`、`manual_required` 和 `legacy_not_resumable`。
- 跨进程只继续审批、验证和确定性 Checkpoint 恢复；不继续正在进行的模型推理或临时工具循环。
- 部分写入只有在全部目标都精确匹配修改前或修改后哈希时才可提出恢复计划，并且必须重新审批。
- 任一未知哈希、证据矛盾、工作区身份变化或 Checkpoint 不完整都进入 `manual_required`。
- 所有 resume 和恢复操作必须幂等，并在执行前重新校验事实。

## 备选方案

### 从所有中断点继续

体验看似完整，但需要持久化供应商请求和任意工具中间状态，且无法证明远端请求是否完成，容易重复副作用，因此不采用。

### 只提供日志，不提供恢复

实现简单，但不能满足阶段二“中断后可恢复”的退出条件，也无法形成可用的最小 Agent Core，因此不采用。

### 启动时自动回滚

可能在用户尚未检查现场时改写工程，并会覆盖中断后的人工作业，因此不采用。

## 后果

- Vera 能准确区分“继续”“放弃”“经批准恢复”和“人工处理”。
- 某些模型中断只能重新运行原目标，不能无依据地声称精确续跑。
- 私有状态会增加恢复快照，需要权限、原子写入和空间管理测试。
- 未来桌面客户端可复用相同恢复报告和 Command/Event，而不复制文件判定逻辑。

## 验证与重审触发器

- 对每个稳定边界和文件应用 failpoint 进行跨实例故障注入测试。
- 重复扫描、resume 和恢复不得重复副作用。
- 若未来供应商提供可靠的请求续传或幂等协议，再单独评审模型中间轮次恢复。
