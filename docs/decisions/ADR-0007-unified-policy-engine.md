# ADR-0007：统一 PolicyEngine 与策略指纹

**状态：** Accepted
**日期：** 2026-09-11

## 背景

阶段一已经具备工作区路径限制、敏感文件保护、命令分类和 Change Set 审批，但判定分散在多个组件中。跨进程恢复若只恢复旧审批而不确认当前策略，会在用户配置或内置规则变化后沿用过期权限。

## 决策

- 新增 UI 无关的 `PolicyEngine`，统一判定路径、工具、命令、Change Set 和恢复动作，但不负责执行副作用。
- 所有判定返回 `PolicyDecision(decision, reason_code, reason, matched_rule, policy_hash)`。
- 固定优先级为：硬性禁止 → 工作区和敏感资源 → 用户级明确授权 → 内置安全规则 → 本次审批。
- 项目配置只能收紧限制或建议验证命令，不能授予权限。
- 用户授权不能覆盖工作区逃逸、敏感凭据、提权、Shell 解释器或宽泛破坏性操作。
- `policy_hash` 由规范化有效规则、内置策略版本和工作区身份计算，不包含秘密。
- Change Set、验证命令和恢复计划审批同时绑定目标哈希、工作区身份和 `policy_hash`。
- resume 前重新判定；策略变化使旧审批失效。
- `/permissions` 和未来桌面客户端读取同一个引擎快照，不从配置副本推断权限。

## 备选方案

### 继续由各组件独立判断

短期改动较小，但恢复、展示和实际执行容易产生不同结论，因此不采用。

### 把项目配置当作授权来源

不可信仓库可以借此扩大本机执行能力，违反工作区安全边界，因此不采用。

### 持久化审批后永久有效

忽略策略与工作区变化，可能使旧授权在新环境中扩大权限，因此不采用。

## 后果

- 权限判定、解释和展示使用同一来源。
- 策略调整会使部分未完成审批需要用户重新确认，这是预期的安全行为。
- 现有路径和命令规则需要逐步迁入引擎，并用决策矩阵防止语义漂移。

## 验证与重审触发器

- 决策矩阵覆盖每种规则来源、优先级冲突和恢复重新判定。
- 相同规范化策略产生相同哈希；无关字段和秘密不进入哈希。
- 若未来引入组织策略或签名策略包，必须扩展来源优先级并重新评审。
