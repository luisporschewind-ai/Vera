# ADR-0012：桌面集成延后至 Core 加固与 CLI 产品化之后

**状态：** Accepted
**日期：** 2026-09-12

> 后续关系：[ADR-0017](ADR-0017-insert-cli-experience-stage.md) 在阶段六与桌面之间新增阶段七 CLI 体验收口；[ADR-0020](ADR-0020-stage-core-native-skills.md) 与 [ADR-0021](ADR-0021-core-tools-before-desktop.md) 又依次在桌面之前插入 Skills 及工具/Policy/Git；[ADR-0023](ADR-0023-insert-core-observability-before-desktop.md) 再插入 Core Trace。当前桌面为阶段十一。本 ADR 的 Core-first、CLI-first 和桌面延后原则继续有效；下文中的旧阶段编号保留当时决策背景。

## 背景

Vera 的长期产品形态仍是桌面 Agent，但当前 CLI 既是 Core 的开发载体，也是最直接的内部验收客户端。阶段四的固定离线评测能够证明 Core Command/Event、安全编辑、恢复和评测链路在冻结脚本下可重复，却不能单独证明真实工程、长会话、异常系统状态和真实模型参与时已经达到桌面集成所需的稳定度。

如果阶段四之后立即投入桌面端，Core 缺口会与窗口生命周期、IPC、打包和前端状态混在一起，扩大定位和返工成本。

## 决策

- 在评测与内部就绪之后增加“Core 安全、权限与可靠性加固”和“CLI 产品化与体验完善”两个阶段，原桌面集成顺延到阶段七。
- 阶段五以现有 `vera`、`vera --plain`、`vera --json` 和 `vera eval` 为 Core 验收表面，不增加第二套 Runtime 或面向 UI 的业务逻辑。
- 阶段六在不改变 Core 权威边界的前提下，完善 TUI、输入、导航、帮助、诊断、Diff 和审批体验。
- 桌面技术验证只有在阶段五与阶段六退出条件全部满足、阶段四独立审查无阻断项，**并且用户明确确认「CLI 版本达到预期，可以封存」** 后才能开始。
- 未获该确认前，不得开始阶段七，也不得引入 Wails、Tauri、Electron 或任何桌面端代码、依赖与 Spike。
- 桌面端仍必须消费 Core 的结构化 Command/Event；不得通过解析 CLI 人类输出接入。
- 阶段五优先处理安全、权限、数据完整性、恢复、安装升级、真实工程适配和长会话稳定性；阶段六负责产品体验，且不能反向削弱这些门禁。
- 真实 Provider 验证只能由用户显式发起并控制凭据；默认自动门禁继续使用 Fake Model，不读取真实 Key。

## 后果

- Core 与 CLI 获得独立成熟窗口，桌面实现可以建立在更稳定的协议和运行时上。
- 路线图增加两个阶段，桌面原型和私有预览时间相应后移。
- 部分 CLI 工作最终不会直接显示在桌面 UI 中，但它形成的安全、恢复和协议能力仍由所有客户端复用。
- 桌面框架当时继续保持开放；用户随后通过 [ADR-0013](ADR-0013-electron-desktop-baseline.md) 确认 Electron 为阶段七首个底版，Tauri 为门禁不达标时的备选。该后续选择不改变本 ADR 的阶段门禁。

## 被拒绝的方案

- **阶段四后立即开发桌面端：** 离线评测覆盖不足以证明真实工程稳定性，容易把 Core 缺陷包进 UI。
- **自动测试或 Textual Pilot 通过后即封存阶段六：** 不能证明真实 Terminal.app 与真实工程中的可用性，禁止以此进入阶段七。
- **把 Core 加固和 CLI 产品化合并成一个阶段：** 安全可靠性会吞掉体验细节，或体验改动会干扰底层缺陷定位。
- **只增加桌面阶段的进入检查：** 无法给 Core 加固和 CLI 产品化提供独立目标、任务顺序和退出定义。
- **插入“阶段 4.5”：** 避免重新编号，但长期路线和任务引用不够清晰。

## 验证与重审触发器

- 阶段五必须形成安全/权限审查、代表性工程内测、恢复与数据完整性、安装升级和长期运行证据。
- 阶段六必须形成主流交互基线、终端兼容、可用性回归和完整 CLI 产品验收证据。自动测试、Textual Pilot 与快照不能代替用户在 Terminal.app 和真实工程中的体验结论。
- 任务 0029 在自动证据齐全后只能进入 `Ready for manual acceptance`。未经用户确认「CLI 版本达到预期，可以封存」，不得将阶段六标为 Complete，不得进入桌面阶段。
- 人工体验中发现的输入、对话、工具展示、Diff、审批、错误、恢复、性能和终端兼容问题，继续作为阶段六修正任务。
- 阶段五存在未解决的 Critical/High 安全问题、未批准副作用、不可恢复的数据损坏或协议分叉时，不得进入桌面阶段。
- 若未来 Core 的协议或进程边界发生根本变化，应重审本决策和桌面进入条件。
