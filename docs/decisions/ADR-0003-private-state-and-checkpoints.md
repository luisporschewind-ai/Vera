# ADR-0003：私有状态、Event Journal 与 Checkpoint

**状态：** Accepted
**日期：** 2026-09-10

## 背景

安全编辑必须能回答“模型提出了什么、用户批准了什么、实际写入了什么、验证结果是什么”，并且在应用失败或用户手动回滚时保留可核对的证据。项目工作区不应被 Vera 的运行日志和恢复数据污染。

## 决策

- Vera 私有状态目录由 `platformdirs.user_state_path("Vera")` 生成；运行记录、Event Journal、Checkpoint 和临时恢复数据都存放在该目录。
- 项目工作区只保存用户项目文件，不写入 Vera 运行状态；项目配置只能降低安全限制，不能提升限制或声明隐式安全命令。
- Event Journal 使用追加写入、连续 sequence 和脱敏 Payload；重新打开时拒绝损坏或不连续的日志。
- 每次文件应用前，Runtime 必须创建与 Change Set 绑定的 Checkpoint，记录原始字节、存在性、权限和哈希。
- 应用与回滚都必须重新核对目标哈希和 Change Set 哈希；发现用户编辑或哈希冲突时拒绝覆盖并保留现场。
- 验证失败保留已应用的现场，由用户显式执行回滚；恢复失败必须返回 `RECOVERY_REQUIRED` 和受影响路径。

## 后果

- 运行记录可查询、可脱敏、可审计，且不会把运行产物混入用户 Git 工作区。
- Checkpoint 增加磁盘占用和实现复杂度，但为应用失败恢复和冲突安全回滚提供明确边界。
- “恢复”不是无条件覆盖；用户在应用后的编辑优先于自动回滚。

## 验证与重审触发器

- 临时 Git Fixture 覆盖批准、拒绝、应用失败、验证失败、用户编辑后回滚冲突和恢复失败。
- 若未来需要崩溃后自动恢复，必须先补充 journal resume、未完成应用状态和幂等策略，再更新本 ADR。
