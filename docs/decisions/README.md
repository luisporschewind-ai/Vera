# Architecture Decisions

Decision records explain durable technical choices and their trade-offs.

## Convention

- Name files `ADR-NNNN-<topic>.md` using the next sequential number.
- Declare one status: `Proposed`, `Accepted`, or `Superseded`.
- Record context, options considered, decision, consequences, and verification or revisit triggers.
- Use a new record to supersede an accepted decision; preserve the prior rationale.

Create a decision record for choices such as the Core runtime, protocol, persistence model, critical dependency, security boundary, or desktop framework. Routine implementation details belong in a task instead.
