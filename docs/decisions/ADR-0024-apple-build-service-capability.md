# ADR-0024：Apple iOS 构建系统服务采用单次具名授权

**状态：** Accepted
**日期：** 2026-09-28
**来源：** 用户要求修改系统服务 Draft，允许此类授权并解决 iOS 构建阻塞
**关联：** [系统服务规格](../specs/2026-09-28-apple-ios-build-service-boundary.md)、[任务 0089](../tasks/0089-apple-toolchain-repair.md)

## 背景

Intel macOS 假 iOS 工程在宿主可构建，当前 SRT 中的 Xcode 因 CoreSimulator 依赖失败。先前只准许文件/工具链读取，系统服务默认拒绝；这不能支持 Xcode 的完整原生构建。即使 generic destination，Xcode 仍引用当前用户的 CoreSimulator Devices 路径，未找到可证明全命令树独立使用的设备集参数。

## 备选方案

1. 继续无条件拒绝 CoreSimulator 服务：保留明确失败，但 iOS 工程构建不可用。
2. 将 Apple 服务加入所有命令默认权限：容易接通部分依赖，但其他项目命令也会得到该能力，用户无法看到或控制风险。
3. Core 维护精确具名服务集合，绑定单次 Xcode 构建与审批：保持默认拒绝，并允许用户明确承担服务端访问当前用户模拟器状态的风险。
4. 独立 Apple 工具链后端：在 SRT 的具名权限仍不能运行 Xcode 时作为后续路线；需要单独验证隔离、部署和性能。

## 决策

选择方案 3 作为授权契约。普通文件授权与命令审批不隐含系统服务权限；Core 必须在审批卡展示服务集合、整棵命令树继承范围及模拟器宿主状态风险，并把能力绑定到精确的一次性构建操作。服务名只来自受审固定清单，项目、模型或环境不能自行扩大。无批准、绑定失效、后端不支持时失败关闭；文件与禁网规则仍执行。

此决策**不认定当前 SRT 后端已经兼容 Xcode**，也不授权通配 Mach lookup、无沙盒宿主回退、签名、设备操作或修改系统设置。单次批准无法回滚服务端已发生的副作用，CLI 与结果必须如实说明。

## 后果与复审触发

授权机制与实际可运行性分开验收。假工程 Storyboard 构建、边界负例、取消/超时清理和真实工程副本验证全部完成前，0089 iOS 构建仍标记未通过。若精确服务集合不能使 SRT 完成构建，停止继续堆叠服务名，转入方案 4 的独立后端评估；不得用默认放权或无沙盒执行掩盖失败。

## 2026-09-28 实施收敛

组合诊断已证明固定六服务（Intel）、独立文件读取与目录节点列举、临时 APFS 产物卷可在 SRT 内完成 Storyboard 构建。选用 Core 每构建创建/卸载/销毁产物卷，不开放宿主共享 TemporaryItems；成本为镜像挂载开销、8 GiB 逻辑上限和无跨次增量缓存，审批必须披露。最终产品路径由用户验收，暂不启动独立 VM 后端，不取消其他生命周期与边界门槛。
