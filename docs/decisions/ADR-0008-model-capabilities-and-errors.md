# ADR-0008：ModelAdapter 能力、错误与有限重试

**状态：** Accepted
**日期：** 2026-09-11

## 背景

Vera 通过 OpenAI-compatible Adapter 接入模型，但不同供应商对 Tool Calling、并行调用、usage 和错误响应的支持并不完全一致。把所有异常折叠为 `model_error` 会失去可诊断性；无边界重试又可能增加成本或重复后续副作用。

## 决策

- 每个 Model Profile 装配时提供 UI 无关的 `ModelCapabilities`。
- 编码 run 在请求前验证必需能力，缺失时返回 `capability_mismatch`。
- Adapter 把异常标准化为配置、认证、网络、超时、限流、服务、无效响应和能力不匹配错误。
- 只有明确瞬时错误可有限重试，默认总尝试次数为二。
- 自动重试只包围单次模型请求，不重复本地工具、审批、文件应用或验证。
- 已经解析出有效 Tool Call 的响应不因后续本地错误重新请求模型。
- 第一版不自动切换 Profile 或供应商。
- 用量证据使用可空字段记录 Token、耗时、attempt 和供应商请求标识；缺失值不能伪造为零。
- 错误和 Event 必须脱敏，不保存原始认证对象或完整请求正文。

## 备选方案

### 继续只返回 model_error

实现简单，但无法制定重试策略、排查供应商兼容问题或形成评测证据，因此不采用。

### 自动切换备用供应商

会静默改变模型行为、成本和数据边界，也增加结果可重复性问题，因此延后。

### 对所有网络异常无限重试

成本和等待时间不可控，且可能隐藏持续故障，因此不采用。

## 后果

- Runtime 可以依据稳定错误码决定是否重试和如何展示。
- DeepSeek、GLM 等 Profile 可复用同一套 conformance tests。
- 某些超时请求可能在供应商侧已经计费；Event 必须保留每次 attempt，不能声称续传。

## 验证与重审触发器

- 使用固定响应 Fixture 覆盖文本、Tool Call、usage、认证、限流、超时、5xx 和格式错误。
- 验证任何重试都不会重复本地副作用。
- 若未来引入自动路由或供应商 failover，必须新建 ADR 定义用户授权、成本和一致性语义。
