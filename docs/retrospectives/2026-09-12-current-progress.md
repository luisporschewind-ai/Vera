## 现在已经具备什么

### 1. 一个 UI 无关的 Vera Core

- `VeraRuntime` 是任务执行权威，终端和未来桌面客户端不复制业务规则。
- Command、Event、`SessionAction`、`RuntimeOutput` 均为结构化契约。
- Provider 通过可替换 Adapter 接入；供应商 SDK 类型不渗入 Core 公共边界。
- `StreamFrame` 只负责瞬时显示，最终事实仍写入持久 Event。

### 2. 一条完整的安全编辑链路

- 收集有界 Workspace 上下文；
- 由模型提出可审阅 Change Set；
- 根据 Policy 和 Workspace 事实请求审批；
- 创建 Checkpoint 后写入；
- 以结构化 argv、cwd 和退出事实执行验证；
- 支持持久化手动回滚，并保护 Vera 之后的用户修改。

### 3. 可以真正看到和操作的 TUI 雏形

- TTY 默认进入 Textual 全屏界面；同时保留 `--plain` 和 `--json`。
- 已有流式回答、可滚动时间线、工具和日志披露、Diff/审批展示。
- Composer 支持多行输入、Slash 补全、审批焦点、取消和活动状态。
- 三种终端模式共用 `SessionController` 和 Vera Core，不是三套 Runtime。

用户当前反馈“已经有点样了”非常关键：这证明前面 Core-first 的工作已经开始转化成可感知的产品界面，而不是只存在于测试和文档中。

### 4. 恢复、策略和评测底座

- 崩溃后依据 Journal、Snapshot、Checkpoint 和 Workspace hash 做只读分类。
- 恢复审批与普通审批共享同一套结构化事实，不建立旁路。
- 未知未来版本、损坏状态和事实变化默认失败关闭。
- 14 个固定离线任务可重复运行，不调用真实 Provider，不读取用户工程。
- 阶段四独立审查记录 64/64 项已检查，没有需要报告的安全漏洞。

### 5. 阶段五已完成的加固

- 任务 0020：路径、文件身份、Workspace 事实和审批绑定进一步加固。
- 任务 0021：子进程监督、进程组清理、环境构造、秘密识别/脱敏和验证执行进一步统一。

## 初版 TUI 反馈应如何理解

这条反馈可以确认：

- TUI 已经不只是命令输出，而是出现明确的 Agent 产品形态；
- 时间线、输入区、流式状态和审批等关键构件的方向基本成立；
- Core 与展示分离没有阻止界面形成，反而为后续桌面复用提供了基础。

但暂时不能据此确认：

- 长文本粘贴、历史、单条队列和恢复输入已经成熟；
- 路径引用、命令目录、诊断和帮助足够顺手；
- 大 Diff、长输出、错误、Resize、Unicode、无色和低速终端没有阻断问题；
- 真实项目中的日常工作流已经达到可封存标准。

这些正是阶段六任务 0025–0029 的范围。当前反馈记录为积极的早期人工证据，不冒充阶段六最终验收。

## 现阶段形成的关键资产

最重要的资产不是某个界面，而是已经形成一条可复用主干：

```text
TUI / Plain / JSON / 未来 Wails
                ↓
结构化 Session 与 Core 契约
                ↓
Runtime / Policy / Workspace / Approval / Recovery
                ↓
受监督工具进程、私有状态和可审阅证据
```

这条主干让 TUI 和未来桌面端只是不同客户端。桌面阶段不需要重做 Agent loop、安全编辑、审批或恢复，这是当前连续开发最有价值的结果。
