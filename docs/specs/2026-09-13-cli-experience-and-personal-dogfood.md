# 阶段七：CLI 体验收口与个人主力化

**状态：** Accepted
**日期：** 2026-09-13
**所属阶段：** 阶段 7——CLI 体验收口与个人主力化（Complete）

## 目的

阶段六回答“Vera CLI 的功能与可靠性是否成立”，阶段七回答“它是否已经成为用户愿意长期使用的个人主力 Coding Agent CLI”。本阶段不以继续堆叠功能为目标，而是收口会话连续性、TUI 视觉识别、信息层级、交互质感和真实使用中的高频摩擦。

Codex CLI、Claude Code 与 Grok Build 作为成熟使用体验的参照，但 Vera 不复制其品牌、云端能力、Multi-Agent、插件市场或未被自身 Core 支持的行为。

## 入口与退出门禁

进入阶段七前：

- 阶段六的任务 0025–0033、任务 0042、相应自动门禁和必要缺陷复验完成；
- 没有未关闭的 Critical/High CLI 正确性或可靠性问题；
- 阶段七规格与任务顺序已经由用户接受。

阶段七不能只靠自动测试、Textual Pilot、SVG 或快照完成。退出必须同时满足：

- TUI、Plain、JSON 和一次性模式没有被视觉改动破坏结构化语义；
- 真实 Terminal.app 与真实工程的持续 dogfood 没有未关闭的 Critical/High 使用缺陷；
- 用户明确原文确认「CLI 版本达到预期，可以封存」。

缺少上述确认时，阶段七保持 `In progress` 或 `Ready for manual acceptance`，所有后续 Core 与桌面阶段都保持 `Not started`。后续架构与文档规划不等于开始实施。

## 范围

### 1. 持久化对话与任务连续性

按[持久化对话会话与个人主力 CLI](2026-09-13-persistent-conversation-sessions.md)实现新建、继续、历史选择、压缩、损坏处理和跨进程恢复。会话只引用权威 run 证据，不复制工具、Diff、审批或恢复状态机。

### 2. 项目指令与初始化

按[项目指令发现与 `VERA.md` 初始化](2026-09-14-project-instructions-and-vera-init.md)实现根目录 `VERA.md` 原生读取、`AGENTS.md` 兼容、`/instructions` 状态和经 Change Set 审批的 `/init`/`vera init`。项目说明只属于 advisory 工程建议，不能扩大权限或自动执行其中命令；普通启动不得静默创建文件。

### 3. Vera CLI 视觉识别

- 为 TUI 启动首屏建立 Vera 专属标识，不再只是通用状态列表。
- Logo 系统提供进场四行加粗点阵、任务后一行拉丁字标，以及 ASCII `.` 回退；不能依赖特定 Nerd Font。
- 延续已确认的克制、优雅、低饱和深海方向，避免廉价霓虹、过强渐变和大面积高亮。
- 窄屏不换另一套紧凑布局，同一结构能显示多少显示多少。
- CLI 先确认可复用的品牌母形与色彩语义；阶段十再扩展桌面应用图标、菜单栏和窗口资产。

### 4. 启动首屏与工作状态

- 首屏首先回答当前工作区、模型、会话、权限边界和可执行下一步，再展示次要诊断信息。
- 新会话、恢复会话、非 Git 目录、dirty workspace 和受限终端具有明确但克制的差异。
- 运行中、等待批准、验证、完成、取消、失败和可恢复状态使用统一的文字、图形与颜色语义。
- 状态不能只依赖颜色，且不得用动画或文案伪造 Core 未提供的进度。
- 顶栏进场为无框欢迎卡：左四行加粗点阵 `VERA`，右为 `Vera` 与包版本、工作区全路径、模型与推理；不写「新会话」或时钟。点阵亮带从左下走到右上。本进程第一次发出任务后收成一行 `VERA  ~/path`，彼此靠近；`/new` 也不展开。
- 助手回答渲染 Markdown：管道表排成表，Diff 与代码按内容宽度可读，路径与中文不从词中切断。
- 运行活动固定在 Composer **上方**的工作轨：当前动作、目标、本轮步骤与取消提示。空闲隐藏。时间线里工具/状态组默认收起，失败才展开。
- Composer 下方底栏左侧为分支（无则省略）、`审批 {mode}`、会话上下文占用；未保存仍可附在左侧。右侧为当前模型与有效推理强度。运行活动不放在底栏。
- 上下文占用默认使用 `ConversationStats.context_bytes / max_bytes`，以短条形进度和 **已用/上限** 呈现（满 1000 字节起用 `K`）；它必须标为“会话上下文”，不能伪装成 Provider 的精确 token 窗口。终端不使用仅靠颜色或难以对齐的环形图。
- 推理强度只显示 Core/Provider 配置确认的有效值；Provider 不支持或未提供时分别显示“不可用”或“模型默认”，不得从模型名、`reasoning_content` 或回答长度推断 `low`/`medium`/`high`。

### 5. 时间线与卡片层级

- 用户消息和助手回复形成对话主轴；工具、日志和恢复事实作为次级证据，不与正文争夺视觉权重。
- 最近一条用户消息在浏览其后续回答与证据时固定为时间线顶部的上下文锚点；下一条用户消息到达锚点时替换上一条。锚点不得覆盖审批、未读提示或 Composer，并保持文本选择与键盘滚动可用。
- 用户消息右侧显示由权威 Event/持久化 Turn 提供的本地时间，默认 `12:49 PM` / `9:21 PM`（英文 AM/PM、无前导零）；钉顶条同一格式。恢复历史时沿用原时间，不以重绘时间代替。时间未知时明确省略，不生成假时间。
- 工具块至少清楚显示动作、目标、状态和耗时；正文按需展开，空块和重复噪音视为阻断体验的问题。
- Diff、审批、验证和失败具有高于普通工具日志的视觉优先级，但不通过大面积警示色制造疲劳。
- 审批卡使用中文标题和字段标签，动作、目标、风险、工作区、影响完整可见；字段标签弱化、值清晰，长影响自然换行。卡片上下各保留一行以内分隔，事实与按钮之间留一行；三个按钮依次显示“取消 / 拒绝 / 批准”，默认焦点仍为取消，在 80×24 主流程内连续可见。
- 同一事实在 TUI、Plain 和 JSON 中保持语义一致，视觉层不得重新推断成功、风险或权限。

### 6. Composer、导航与空间密度

- Composer 在空闲、运行、排队和等待批准时具有稳定位置与清楚状态，不因时间线刷新跳动。
- Composer 文本左侧提供独立提示箭头：Unicode 使用克制的单字符箭头，能力不足时回退为 ASCII `>`；箭头不属于草稿文本，不参与提交、历史、复制或上下文计量，多行输入只显示一个提示箭头。
- 80×24 是完整主流程基线；60×16 安全降级；120×40 可以增加证据密度但不改变操作语义。
- 统一边框、圆角替代符号、间距、缩进、标题、快捷键提示和焦点样式，减少“组件拼装感”。
- 鼠标可用但不是必需；键盘焦点、复制、滚动、折叠和返回底部必须可靠。

### 7. 主题与可访问性

- 默认主题采用 Vera 深海方向，并保留高对比与无色回退。
- 尊重 `NO_COLOR`、`TERM=dumb`、`VERA_NO_ANIMATIONS` 和 reduced-motion 配置。
- CJK、英文、Emoji、宽字符和常见 Terminal.app 字体下不重叠、不破坏关键审批信息。
- 颜色、符号和动画只增强理解，不能成为唯一状态来源。

### 8. 个人长期 dogfood

- 使用真实 Terminal.app 和真实工程完成连续多轮任务，而不是只运行演示脚本。
- 记录启动、理解工程、修改、审批、Diff、验证、取消、恢复、退出继续和长会话中的摩擦。
- 缺陷按正确性、可靠性、交互阻断和视觉瑕疵分级；Critical/High 必须关闭，Medium 必须有明确处置。
- 只有用户本人能够给出最终 CLI 封存确认。

## 非目标

- 不添加 Electron、Tauri、Wails 或其他桌面代码、依赖和技术 Spike。
- 不实现桌面窗口、桌面应用图标、菜单栏资产或桌面四区工作台。
- 不新增 Multi-Agent、复杂 RAG、插件市场、云同步或账号系统。
- 不为了视觉重构改变 Core 权威、审批边界、工具权限或结构化协议语义。
- 不建设任意第三方主题市场或可执行主题系统。
- 不以截图相似度代替真实可用性，也不要求复制任何竞品界面。

## 计划增量

任务级实施计划见[阶段七实施计划](../tasks/phase-7-execution-order.md)，按以下依赖顺序拆分：

1. 持久化会话 Core 与跨进程恢复；
2. 根目录项目指令发现、可见状态与 `VERA.md` 审批初始化；
3. Vera CLI 标识、设计 token 与三类主题基线；
4. 启动首屏、状态区、时间线与卡片视觉收口；
5. Composer、焦点、导航、小终端与长内容体验；
6. wheel 安装、Terminal.app 和真实工程完整回归；
7. 持续个人 dogfood 与最终封存。

每个增量只允许一个主实现 Agent；视觉实现也必须通过同一 SessionController、View Model 和结构化 Core 事实，不得在 Widget 中加入业务或权限逻辑。

## 验收方向

1. 启动 `vera` 后可以立即识别 Vera、当前工作区、会话状态、模型和权限边界。
2. 默认深海主题、Unicode 紧凑形态、纯 ASCII、高对比和无色回退均可用。
3. 用户、助手、工具、Diff、审批、验证、失败和恢复状态具有清楚且一致的信息层级。
4. 用户消息锚点在滚动中稳定、右侧时间来自原始事实；下一条用户消息正确替换锚点，恢复历史不改写时间。
5. Composer 左侧箭头不进入草稿或提交内容；下方状态带在 80×24 最左显示运行状态，随后为上下文短条与已用/上限（K）、右侧为模型和有效推理强度，并在窄屏按已接受优先级安全降级。
6. 审批卡上下没有中断性空白，动作事实和 Cancel/Reject/Approve 在主尺寸连续可见。
7. 60×16、80×24、120×40 与 Resize 场景不遮挡输入、不丢失审批事实、不破坏滚动位置。
8. 持久化会话支持退出、继续、选择历史和安全失败，不重复工作区副作用。
9. `VERA.md`/`AGENTS.md` 项目说明可观察且不授予权限，`/init` 不经批准不写工作区。
10. TUI 视觉修改不改变 Plain/JSON 语义，不让桌面客户端未来依赖人类文本。
11. 完整非 live、PTY、Textual Pilot、快照、Ruff、格式、Mypy、构建、wheel smoke 和 `git diff --check` 通过。
12. 用户在真实 Terminal.app 和真实工程中持续使用后，明确确认「CLI 版本达到预期，可以封存」。
