# Specifications

Specifications define observable product behavior and acceptance criteria before implementation.

## Convention

- Name files `YYYY-MM-DD-<topic>.md`.
- Declare one status: `Draft`, `Accepted`, or `Superseded`.
- Include goal, non-goals, user flow or system behavior, boundaries, failure behavior, and verifiable acceptance criteria.
- Link decisions that constrain the design and tasks that implement it.
- Do not implement a draft specification unless the user explicitly authorizes a time-boxed spike.

Keep each specification small enough to produce one independently verifiable product increment.
